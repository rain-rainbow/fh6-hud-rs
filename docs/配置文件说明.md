# 配置文件说明

`fh6-hud.config.json` 是三个程序（`fh6-hud`、`fh6-relay`、图形界面）共用的
唯一配置文件。默认位置：**可执行文件同目录**。

> 为什么用「exe 同目录」而不是 `%APPDATA%`：让「绿色版」真的绿色 ——
> 整个文件夹拷走就带着配置，不用去别处找，也不用给用户解释两个路径的关系。

## 加载与保存规则

| 情况 | 行为 |
|---|---|
| 文件不存在 | 静默使用内置默认值（首次运行的正常路径） |
| JSON 语法错误 | 回退默认值，并在控制台/界面提示 |
| 字段缺失 | 该字段取默认值（所有结构体都 `#[serde(default)]`） |
| 字段越界 | 夹紧到合法范围，并提示「已自动修正」 |
| **旧版格式**（顶层直接是外观参数） | **自动迁移**到新格式的 `hud` 段并提示 |
| 保存 | **原子写入**：先写 `.tmp` 再 `rename`，中途崩溃不会留下半截文件 |
| 未知字段 | 忽略（保证向前兼容） |

命令行参数的优先级**高于**配置文件，方便临时调试。

## 顶层结构

```json
{
  "version": 1,
  "hud":     { ... },   // 外观与 HUD 监听端点
  "relay":   { ... },   // relay 监听端点与分发目标
  "logging": { ... },   // 日志文件
  "apps":    { ... }    // GUI 的应用路径与启动行为
}
```

## `hud` —— 外观与 HUD 监听端点

### 语言与网络

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `language` | `"zh"` \| `"en"` | `"zh"` | 界面语言。中文下行距会自动放大（见 ADR-013） |
| `network.listen_ip` | string | `"127.0.0.1"` | HUD 收包地址。填 `0.0.0.0` 可接收局域网，但会暴露端口 |
| `network.listen_port` | u16 | `5302` | HUD 收包端口。应等于 relay 的某个分发目标端口 |

### 全局变换

| 字段 | 类型 | 范围 | 默认 | 说明 |
|---|---|---|---|---|
| `global_scale` | f32 | 0.25–4 | 1.0 | 整体缩放（以各元素自身坐标为基准） |
| `offset_x` | f32 | -4000–4000 | 0 | 整体水平偏移 |
| `offset_y` | f32 | -4000–4000 | 0 | 整体垂直偏移 |

| `arc_width` | 1–80 | 18 | 轨道宽度 |
| `glow_strength` | 0–1 | 0.35 | 辉光强度 |
| `glow_layers` | 0–8 | 3 | 辉光层数 |

### G 表 `g_meter`

| 字段 | 范围 | 默认 | 说明 |

### 条形面板 `input_panel` / `slip_panel` / `flow_panel`

## `relay` —— 监听端点与分发目标

| 字段 | 默认 | 说明 |
|---|---|---|
| `listen_ip` | `"127.0.0.1"` | relay 收包地址（游戏内「数据输出IP地址」填这个） |
| `listen_port` | `5301` | relay 收包端口（游戏内「数据输出IP端口」填这个） |
| `verbose` | false | 是否逐包打印 |
| `targets` | 见下 | **有序**的分发目标列表，数量可任意（上限 32） |

### `targets[]` —— 每一项

| 字段 | 类型 | 说明 |
|---|---|---|
| `enabled` | bool | 是否启用。禁用后保留在配置里但不转发 |
| `host` | string | 目标主机（IP 或域名） |
| `port` | u16 | 目标端口 |
| `label` | string | 显示名称，仅用于日志与界面 |

默认两个目标：

```json
[
  { "enabled": true, "host": "127.0.0.1", "port": 5300, "label": "飞智自适应扳机" },
  { "enabled": true, "host": "127.0.0.1", "port": 5302, "label": "HUD" }
]
```

### 一条自动生效的安全约束

**若某个目标的地址与端口等于 relay 自己的监听端点，relay 会把转发出去的包
再收回来，再次转发 —— 形成自激包风暴，瞬间打满 CPU。**

因此加载配置时会自动**禁用**这类目标（`127.0.0.1` / `localhost` / `::1`
视为等价回环；监听 `0.0.0.0` 时同端口的目标也一律禁用）。这条有专门的单元测试。

## `logging` —— 日志文件

| 字段 | 默认 | 说明 |
|---|---|---|
| `enabled` | **false** | 是否写文件。关闭时**完全不做磁盘 I/O** |
| `path` | `"logs/fh6.log"` | **相对路径按可执行文件所在目录解析**（不是工作目录） |
| `level` | `"info"` | `error` / `warn` / `info` / `debug` |
| `max_bytes` | 8388608（8 MB） | 单文件上限，超过即轮转；夹紧到 4 KB–1 GB |
| `keep_files` | 3 | 保留历史份数（0–50） |
| `console` | true | 是否同时输出到控制台 |
| `per_component` | **true** | 让 HUD 与 relay 各写自己的文件 |

### 日志到底在哪个文件

`per_component = true`（默认）时，`path` 被当作**基础名**，按组件派生：

| 组件 | 实际文件 |
|---|---|
| `fh6-hud.exe` | `logs/fh6-hud.log` |
| `fh6-relay.exe` | `logs/fh6-relay.log` |

设成 `false` 则两者共用 `path` —— **不推荐**：两个进程同时追加会让行交错，
各自的轮转逻辑也会互相干扰（都以为自己是唯一写者）。

### 为什么相对路径不按工作目录解析

同一个程序用不同方式启动时工作目录会变：

| 启动方式 | 工作目录 |
|---|---|
| 双击 exe | exe 所在目录 |
| 从 GUI 启动 | GUI 显式指定的目录 |
| 命令行 `cd` 到别处再运行 | 你当时那个目录 |

若按工作目录解析，日志就会散落到不同位置 —— 排查问题时最怕「我明明开了日志，
却找不到文件」。因此统一按 **exe 所在目录** 解析，任何启动方式结果都一样。

启动时程序会**打印实际使用的日志路径**，GUI 的「打开日志目录」也用同一规则
（以 HUD 可执行文件所在目录为基准），两者必然一致。

### 时间戳是 UTC

格式形如 `2026-10-19 15:32:06Z`，**末尾的 `Z` 表示 UTC**，不是本地时间。
北京时间需 +8 小时。之所以不做本地时间：`fh6-config` 禁止 `unsafe`，
取不到 Windows 时区偏移；与其悄悄写成 UTC 却不标注，不如显式标出来。

### 轮转机制

```text
fh6-hud.log      → fh6-hud.log.1
fh6-hud.log.1    → fh6-hud.log.2
...
fh6-hud.log.(N-1)→ fh6-hud.log.N   （超出的删除）
fh6-hud.log      → 新建
```

磁盘占用上界约为 `max_bytes × (keep_files + 1)`，可预测。

日志写入失败（路径不可写、磁盘满）**绝不影响主功能**：退化为仅控制台，静默丢弃该行。

## `apps` —— GUI 的应用路径与启动行为

| 字段 | 默认 | 说明 |
|---|---|---|
| `hud_exe` | `""` | HUD 可执行文件路径。**空 = 自动查找** |
| `relay_exe` | `""` | relay 可执行文件路径。**空 = 自动查找** |
| `auto_start` | false | 启动界面时自动拉起两个进程 |
| `close_to_tray` | **true** | 关闭窗口时收到托盘而不是退出 |
| `confirm_close` | **true** | 最小化前弹出系统确认框（是/否/取消 = 最小化/退出/不关闭） |

### 自动查找的顺序

1. 配置里显式写明的路径；
2. GUI 可执行文件所在目录；
3. 从该目录逐级向上（最多 8 层），以及每一层的 `target/release/`、`bin/`。

这样同时覆盖「开发目录」与「打包目录」两种形态。
